# Spark Streaming Application

Real-time event processing for music streaming data pipeline using Apache Spark Structured Streaming.

## 🎯 Overview

This application consumes streaming events from **multiple Kafka topics**, transforms them, and writes to Google BigQuery for analytics.

### Supported Kafka Topics

The application reads from 4 event types generated by eventsim:

| Kafka Topic | Event Type | Description | Key Fields |
|-------------|------------|-------------|------------|
| `listen_events` | `song_play` | User plays a song | artist, song, duration |
| `page_view_events` | `page_view` | Page navigation | page, method, status |
| `auth_events` | `authentication` | Login/Logout | auth, level |
| `status_change_events` | `status_change` | Subscription changes | level, auth |

## 🚀 Quick Start

### Prerequisites
- Python 3.9+
- Apache Spark 3.5.0
- Access to Kafka cluster
- Google Cloud Platform account with BigQuery

### Installation

```bash
cd spark-streaming
pip install -r requirements.txt
```

### Configuration

Edit `config/config.yaml`:

```yaml
# GCP Configuration
gcp:
  project_id: "your-gcp-project-id"
  dataset_id: "music_streaming_data"
  table_id: "raw_events"
  credentials_path: "credentials/gcp-service-account-key.json"

# Kafka Configuration
kafka:
  bootstrap_servers: "localhost:9092"  # or kafka:29092 for Docker
  
  # Multiple topics configuration
  topics:
    multiple:
      - "listen_events"
      - "page_view_events"
      - "auth_events"
      - "status_change_events"
  
  topic_mode: "multiple"  # single | multiple | pattern
```

### Topic Modes

The application supports 3 topic subscription modes:

#### 1. **Multiple Topics** (Recommended)
Subscribe to specific list of topics:
```yaml
topic_mode: "multiple"
topics:
  multiple:
    - "listen_events"
    - "page_view_events"
    - "auth_events"
```

#### 2. **Single Topic**
Subscribe to one topic only:
```yaml
topic_mode: "single"
topics:
  single: "listen_events"
```

#### 3. **Pattern Matching**
Subscribe using regex pattern:
```yaml
topic_mode: "pattern"
topics:
  pattern: ".*_events"  # Matches all topics ending with _events
```

### Running the Application

```bash
# Local development
python src/main.py

# With specific config
python src/main.py --config config/config.yaml
```

## 📊 Data Flow

```
Kafka Topics (4)  →  Spark Streaming  →  BigQuery
                           ↓
                    Transformations:
                    - Add event_id (UUID)
                    - Add event_type (from topic)
                    - Convert timestamps
                    - Parse locations
                    - Data quality checks
                    - Filter unwanted events
```

## 🔄 Transformations

### Event Type Mapping
The application automatically adds `event_type` field based on Kafka topic:

```python
kafka_topic          → event_type
------------------      ------------
listen_events        → song_play
page_view_events     → page_view
auth_events          → authentication
status_change_events → status_change
```

### Additional Transformations
- **event_id**: UUID for each event
- **processed_at**: Processing timestamp
- **processing_date**: Date for partitioning
- **Location parsing**: Extract city, state from location string
- **Timestamp conversion**: Milliseconds → proper timestamps

### Data Quality
- Drop null `page` and `ts` fields
- Keep null `userId` (guest users are valid)
- Filter out "Cancel" and "Downgrade" pages
- Trim string fields

## 🛠️ Configuration Reference

### Kafka Settings
```yaml
kafka:
  bootstrap_servers: "kafka:29092"
  
  topics:
    single: "listen_events"
    multiple: ["listen_events", "page_view_events", ...]
    pattern: ".*_events"
  
  topic_mode: "multiple"  # single | multiple | pattern
  
  consumer:
    group_id: "spark-streaming-consumer"
    auto_offset_reset: "earliest"
    max_poll_records: 500
```

### Spark Settings
```yaml
spark:
  app_name: "MusicStreamingPipeline"
  
  streaming:
    trigger_interval: "30 seconds"
    checkpoint_location: "/opt/spark/checkpoints"
    max_offsets_per_trigger: 10000
  
  performance:
    shuffle_partitions: 10
    executor_memory: "2g"
    driver_memory: "1g"
```

### Processing Settings
```yaml
processing:
  data_quality:
    drop_null_page: true
    drop_null_ts: true
    drop_null_userId: false  # Keep guest users
  
  transformations:
    add_event_id: true
    add_event_type: true      # Based on kafka topic
    extract_location: true
    add_processing_timestamp: true
  
  filters:
    exclude_pages: ["Cancel", "Downgrade"]
```

## 🐛 Troubleshooting

### Issue: No data flowing from Kafka
**Solution:**
1. Check if eventsim is running and generating events
2. Verify topics exist: `kafka-topics --list`
3. Test consuming: `kafka-console-consumer`
4. Check Spark logs for errors

### Issue: LEADER_NOT_AVAILABLE error
**Solution:**
1. Topics are empty - restart eventsim
2. Kafka not fully ready - wait 30 seconds
3. Check topic names in config match actual topics

### Issue: BigQuery write failures
**Solution:**
1. Verify credentials file exists
2. Check GCP service account has BigQuery permissions
3. Verify project_id in config.yaml
4. Test credentials: `gcloud auth activate-service-account`
