# Eventsim Data Format Documentation

## Overview
This document describes the data format generated by eventsim for the music streaming pipeline. Eventsim generates synthetic user events that simulate realistic behavior on a music streaming platform (similar to Spotify).

**Generation Date**: January 28, 2026  
**Event Period**: January 1, 2024 - December 31, 2024  
**Users**: 1000  
**Total Events Generated**: 1,370,000+  

---

## Event Topics

Eventsim publishes events to multiple Kafka topics based on event type:

| Topic                  | Description                 | Event Types                                  |
| ---------------------- | --------------------------- | -------------------------------------------- |
| `listen_events`        | Song play events            | Songs listened to by users                   |
| `page_view_events`     | Page navigation events      | All page interactions (Home, Settings, etc.) |
| `status_change_events` | Subscription status changes | Upgrades, downgrades, cancellations          |
| `auth_events`          | Authentication events       | Login, logout, registration                  |

---

## Common Event Fields

All events share the following base fields:

### Temporal Fields

| Field           | Type                | Required | Description                                       | Example         |
| --------------- | ------------------- | -------- | ------------------------------------------------- | --------------- |
| `ts`            | INTEGER (timestamp) | Yes      | Event timestamp in milliseconds since Unix epoch  | `1704067440000` |
| `itemInSession` | INTEGER             | Yes      | Sequential item number within the current session | `0`, `23`, `5`  |

### Session Fields

| Field       | Type    | Required | Description                            | Example                                                 |
| ----------- | ------- | -------- | -------------------------------------- | ------------------------------------------------------- |
| `sessionId` | INTEGER | Yes      | Unique identifier for the user session | `1640`, `434`                                           |
| `auth`      | STRING  | Yes      | Authentication status                  | `"Guest"`, `"Logged In"`, `"Logged Out"`, `"Cancelled"` |
| `level`     | STRING  | Yes      | Subscription level                     | `"free"`, `"paid"`                                      |

### User Fields

| Field          | Type                | Required    | Description                                   | Example                 |
| -------------- | ------------------- | ----------- | --------------------------------------------- | ----------------------- |
| `userId`       | INTEGER             | Conditional | Unique user identifier (null for Guest users) | `335`, `435`            |
| `firstName`    | STRING              | Conditional | User's first name (only shown when logged in) | `"Ailyn"`, `"Jonathan"` |
| `lastName`     | STRING              | Conditional | User's last name (only shown when logged in)  | `"Benson"`, `"Farley"`  |
| `gender`       | STRING              | Conditional | User's gender                                 | `"F"`, `"M"`            |
| `registration` | INTEGER (timestamp) | Conditional | User registration timestamp in milliseconds   | `1704067200000`         |

### Location Fields

| Field   | Type   | Required | Description               | Example                      |
| ------- | ------ | -------- | ------------------------- | ---------------------------- |
| `city`  | STRING | Yes      | User's city               | `"Amarillo"`, `"Cornville"`  |
| `state` | STRING | Yes      | US state code (2 letters) | `"TX"`, `"AZ"`               |
| `zip`   | STRING | Yes      | US ZIP code               | `"79109"`, `"86325"`         |
| `lat`   | FLOAT  | Yes      | Latitude coordinate       | `35.166416`, `34.734673`     |
| `lon`   | FLOAT  | Yes      | Longitude coordinate      | `-101.886423`, `-111.897955` |

### Device Fields

| Field       | Type   | Required | Description                      | Example                                                       |
| ----------- | ------ | -------- | -------------------------------- | ------------------------------------------------------------- |
| `userAgent` | STRING | Yes      | Browser/device user agent string | `"Mozilla/5.0 (Windows NT 6.1; WOW64) AppleWebKit/537.36..."` |

### 2. Page View Events (`page_view_events`)

**Description**: Events representing all page navigation and interactions

**Topic**: `page_view_events`

#### Additional Fields

| Field      | Type    | Required    | Description                             | Example                                                                                                                                           |
| ---------- | ------- | ----------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `page`     | STRING  | Yes         | Page name/action                        | `"NextSong"`, `"Home"`, `"Downgrade"`, `"Upgrade"`, `"Settings"`, `"About"`, `"Help"`, `"Login"`, `"Logout"`, `"Register"`, `"Cancel"`, `"Error"` |
| `method`   | STRING  | Yes         | HTTP method used                        | `"GET"`, `"PUT"`, `"POST"`                                                                                                                        |
| `status`   | INTEGER | Yes         | HTTP status code                        | `200`, `307`, `404`                                                                                                                               |
| `artist`   | STRING  | Conditional | Artist name (only for NextSong pages)   | `"Murskahumppa"`                                                                                                                                  |
| `song`     | STRING  | Conditional | Song title (only for NextSong pages)    | `"Stora kusetus"`                                                                                                                                 |
| `duration` | FLOAT   | Conditional | Song duration (only for NextSong pages) | `92.23791`                                                                                                                                        |

#### Page Types

- **NextSong**: Song play page (PUT 200)
- **Home**: Home page (GET 200)
- **Settings**: User settings page (GET 200)
- **Upgrade**: Upgrade to paid subscription page (GET 200)
- **Downgrade**: Downgrade to free subscription page (GET 200)
- **About**: About page (GET 200)
- **Help**: Help page (GET 200)
- **Login**: Login action (PUT 307)
- **Logout**: Logout action (PUT 307)
- **Register**: Registration page (GET 200)
- **Cancel**: Account cancellation action (PUT 307)
- **Submit Upgrade**: Submit upgrade form (PUT 307)
- **Save Settings**: Save settings action (PUT 307)
- **Cancellation Confirmation**: Cancellation confirmed (GET 200)
- **Error**: Error page (GET 404)

## User Behavior Patterns

### Authentication States

- **Guest**: Unauthenticated users (userId is null, user details not shown)
- **Logged In**: Authenticated active users
- **Logged Out**: Previously authenticated users who logged out
- **Cancelled**: Users who cancelled their subscription

### Subscription Levels

- **free**: Free tier users (can listen with ads)
- **paid**: Premium subscription users (ad-free, additional features)

### Session Behavior

Sessions represent continuous user activity periods with:

- Unique `sessionId` for each session
- Sequential `itemInSession` counter (starts at 0)
- Session ends after 30 minutes of inactivity (configurable via `session-gap` in config)

## Event Generation Configuration

### Key Configuration Parameters (from `example-config.json`)

| Parameter         | Value       | Description                                                |
| ----------------- | ----------- | ---------------------------------------------------------- |
| `alpha`           | 90.0        | Controls user activity distribution                        |
| `beta`            | 604800.0    | Controls inter-event time distribution (seconds in a week) |
| `damping`         | 0.09375     | Damping factor for event rate                              |
| `weekend-damping` | 0.5         | Reduces activity on weekends                               |
| `session-gap`     | 1800        | Session timeout in seconds (30 minutes)                    |
| `churned-state`   | "Cancelled" | State representing churned users                           |

### Page Transition Probabilities

The configuration defines Markov chain transition probabilities between pages:

- **NextSong → NextSong**: 50% (users continue listening)
- **Home → Register**: 30% (guest users likely to register)
- **Upgrade page → Submit Upgrade**: 30% (users upgrading)
- **Settings → Cancel**: 0.5% (small chance of cancellation)

### Level Distribution

- **Free users**: 10 weight (83%)
- **Paid users**: 2 weight (17%)

## Data Quality Notes

### Field Nullability

1. **Always Present**: `ts`, `sessionId`, `auth`, `level`, `itemInSession`, location fields, `userAgent`
2. **Conditional on Authentication**:
   - `userId`, `firstName`, `lastName`, `gender`, `registration`: Only present when `auth` is "Logged In" or "Cancelled"
   - Null when `auth` is "Guest" or "Logged Out"
3. **Conditional on Event Type**:
   - `artist`, `song`, `duration`: Only present for NextSong/listen events
   - `page`, `method`, `status`: Only present in page_view_events
   - `success`: Only present in auth_events

### Timestamp Format

- All timestamps are in **milliseconds since Unix epoch** (January 1, 1970)
- Example: `1704067440000` = January 1, 2024, 00:04:00 UTC

### User Agent Strings

User agents are sometimes double-quoted in JSON:

```json
"userAgent": "\"Mozilla/5.0 (Windows NT 6.1; WOW64)...\""
```

May need to strip extra quotes during processing.

## BigQuery Schema Mapping

When ingesting into BigQuery, the schema maps as follows:

| Eventsim Field | BigQuery Field    | BigQuery Type | Transformation                    |
| -------------- | ----------------- | ------------- | --------------------------------- |
| `ts`           | `ts`              | TIMESTAMP     | Convert milliseconds to TIMESTAMP |
| `userId`       | `userId`          | STRING        | Cast to STRING (nullable)         |
| `artist`       | `artist`          | STRING        | Direct mapping                    |
| `song`         | `song`            | STRING        | Direct mapping                    |
| `duration`     | `length`          | FLOAT64       | Rename: duration → length         |
| `userAgent`    | `userAgent`       | STRING        | Remove extra quotes if present    |
| -              | `event_id`        | STRING        | Generate UUID for each event      |
| -              | `processed_at`    | TIMESTAMP     | Add processing timestamp          |
| -              | `processing_date` | DATE          | Extract DATE(ts) for partitioning |

## Usage in Spark Streaming Pipeline

The Spark Streaming application consumes from these topics and:

1. **Reads** events from Kafka (configured topic in `config.yaml`)
2. **Parses** JSON events into structured DataFrames
3. **Transforms** data:
   - Convert timestamp from milliseconds to TIMESTAMP
   - Generate unique event_id (UUID)
   - Clean user agent strings
   - Add processing metadata
4. **Filters** events based on data quality rules:
   - Drop events with null `page` or `ts`
   - Filter out "Cancel" and "Downgrade" pages (configurable)
   - Keep guest users (null userId)
5. **Writes** to BigQuery `music_streaming_data.raw_events` table
